# The filter decline-reasons catalog

Every reason the library declines or refuses a filter, for each supported ClickHouse line. A decline is a row verdict `d`, the status `CHS_DECLINED` or `unsupported`; a refusal is a check the server's own analyzer makes (`CHS_REJECTED`). The catalog is generated by the artifact producer and copied here byte for byte. It is data, outside `spec/abi-v2/abi.json`, so it never moves `CHS_ABI_FINGERPRINT`.

A consumer that receives a decline can map it to its documented cause: what triggered it, which call returns it, on which lines, and whether and when it goes away. See the verdict model in `spec/abi-v2/docs.md` (`filter_verdict`) for what a verdict means, and `spec/abi-v2/where-settings/README.md` for the settings the library declines by name.

## The file

`declines.json` has `schema` (`chtypes.filter-declines/1`), `generator`, `lines` (the supported ClickHouse lines) and `declines`, a list of entries. Each entry has these fields:

| field         | meaning                                                                                                                                                                                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`          | the entry's stable name, unique in the file                                                                                                                                                                                                                                          |
| `class`       | the kind of decline (below)                                                                                                                                                                                                                                                          |
| `trigger`     | what input causes it, in one phrase                                                                                                                                                                                                                                                  |
| `code`        | what the caller sees: `chs`, the library's status or code (`CHS_DECLINED`, `CHS_REJECTED`, `-2` for a per-row or per-document decline, or `ch` when the server's own code is returned), and `ch`, the list of ClickHouse error codes the server may return, empty when none is fixed |
| `lines`       | the supported lines the entry applies to; each is one of the file's top-level `lines`                                                                                                                                                                                                |
| `paths`       | the calls that can return it (`chs_filter_create`, `chs_filter_eval_body`, `chs_filter_eval_block`, `chs_preview_batch`)                                                                                                                                                             |
| `retirement`  | `none` (a permanent rule), or the condition under which the entry goes away, such as a line leaving the supported set or a new filter path shipping                                                                                                                                  |
| `description` | why the library declines it and what a caller can do                                                                                                                                                                                                                                 |

## The classes

- `decline`: the library cannot answer the WHERE for these rows, so every row of the evaluation is declined (`d`), because the server's own result cannot be reproduced.
- `server-check`: the server's own check refuses the WHERE (its parser, analyzer or type gates, or the predicate throwing on a row). The server's code and message are returned.
- `create-decline`: `chs_filter_create` declines (`CHS_DECLINED`) a filter, a query parameter or a schema it cannot accept, and names the cause.
- `call-decline`: a per-call setting or argument the call cannot honor makes the whole call `unsupported`, so every row of an attached filter is declined.
- `row-decline`: a single row is declined with its own reason, because it cannot exist in the table or cannot be stored.
- `batch-precedence`: a batch whose outcome is not `accepted` declines every row, and the filter document's outcome mirrors the batch's.

## Using it

Take the code or reason a call returned, find the entry whose `class`, `paths` and `trigger` match it, and read its `description` and `retirement`. An entry applies on a line only when that line is in its `lines`. A value the catalog does not list is read as unknown, as everywhere in the v2 contract (rule r3); a caller fails closed on it.
