# The filter decline-reasons catalog

Every reason the library declines or refuses a filter, a call or a row, for each supported ClickHouse line, and the caller misuse that names a reason. A decline is a row verdict `d`, the status `CHS_DECLINED`, the outcome `unsupported` or a declined export; a refusal is a check the server's own analyzer makes (`CHS_REJECTED`, or an `e` verdict carrying the server's code); misuse is `CHS_INVALID_ARGUMENT`. The catalog is generated by the artifact producer and copied here byte for byte. It is data, outside `spec/abi-v2/abi.json`, so it never moves `CHS_ABI_FINGERPRINT`.

**This file is the published catalog that rule r4 freezes** (`spec/abi-v2/docs.md`, Rules): an `id` keeps its meaning from the first release that carries it, a retired entry stays here under its `id` with a `retirement` naming its successors, and an `id` is never reused for another meaning.

A consumer that receives a decline can map it to its documented cause: what triggered it, which call returns it, on which lines, and whether and when it goes away. See the verdict model in `spec/abi-v2/docs.md` (`filter_verdict`) for what a verdict means, and `spec/abi-v2/where-settings/README.md` for the settings the library declines by name.

## The file

`declines.json` has `schema` (`chtypes.filter-declines/1`), `generator`, `lines` (the supported ClickHouse lines) and `declines`, a list of entries. Each entry has these fields:

| field             | meaning                                                                                                                                                                                                                                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`              | the entry's stable name, unique in the file                                                                                                                                                                                                                                                                             |
| `class`           | the kind of decline (below)                                                                                                                                                                                                                                                                                             |
| `trigger`         | what input causes it, in one phrase                                                                                                                                                                                                                                                                                     |
| `code`            | what the caller sees: `chs`, the library's status or code (`CHS_DECLINED`, `CHS_REJECTED`, `CHS_INVALID_ARGUMENT` for misuse, `-2` for a per-row or per-document decline, or `ch` when the server's own code is returned), and `ch`, the list of ClickHouse error codes the server may return, empty when none is fixed |
| `lines`           | the supported lines the entry applies to; each is one of the file's top-level `lines`                                                                                                                                                                                                                                   |
| `paths`           | the calls that can return it, such as `chs_filter_create`, `chs_schema_create`, `chs_filter_eval_body`, `chs_filter_eval_block` and `chs_preview_batch`                                                                                                                                                                 |
| `retirement`      | `none` (a permanent rule), or the condition under which the entry goes away, such as a line leaving the supported set or a new filter path shipping; `retired: replaced by …` marks an entry the library no longer emits, which stays so its `id` is never reused and names the ids that replaced it                    |
| `load_dependence` | present on the admission-budget entries only: `deterministic` (the same input, build and profile decline again, so a retry does not help) or `load-dependent` (the host's load can decide near the budget; the `description` says where)                                                                                |
| `description`     | why the library declines it and what a caller can do                                                                                                                                                                                                                                                                    |

## The classes

- `decline`: the library cannot answer the WHERE for these rows, so every row of the evaluation is declined (`d`), because the server's own result cannot be reproduced.
- `server-check`: the server's own check refuses the WHERE (its parser, analyzer or type gates, or the predicate throwing on a row). The server's code and message are returned.
- `create-decline`: `chs_filter_create` or `chs_schema_create` declines (`CHS_DECLINED`) a filter, a query parameter or a schema it cannot accept, and names the cause.
- `call-decline`: a per-call setting or argument the call cannot honor makes the whole call `unsupported`, so every row of an attached filter is declined; or the build declines an input it will not compile again (rule r8).
- `row-decline`: a single row is declined with its own reason, because it cannot exist in the table, cannot be stored, or an evaluation over it exceeded an admission budget (at `chs_schema_create`, the schema is declined).
- `batch-precedence`: a batch whose outcome is not `accepted` declines every row, and the filter document's outcome mirrors the batch's.
- `export-decline`: the batch is answered and its export is declined: no export bytes, `export_declined` names the cause and `export_declined_reason` this `id`.
- `misuse`: the call is refused as caller misuse, `CHS_INVALID_ARGUMENT`, naming the key or the call. The error still carries this `id` (`chs_error_reason`), so a consumer keys on it exactly as on a decline's.

## Using it

Take the reason a call returned (`chs_error_reason`, or a document's `reason`, `verdict_reason` or `export_declined_reason`), find the entry with that `id`, and read its `description` and `retirement`. An entry applies on a line only when that line is in its `lines`. A value the catalog does not list is read as unknown, as everywhere in the v2 contract (rule r3); a caller fails closed on it.
