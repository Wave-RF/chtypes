# The documented platform differences

A short list of exact cells where, on one platform and one ClickHouse line, the server refuses what the library answers, for a reason that belongs to that platform's server build and not to the library. The list is generated by the artifact producer and copied here byte for byte. It is data, outside `spec/abi-v2/abi.json`, so it never moves `CHS_ABI_FINGERPRINT`.

## What a row is

One row is one exact cell: one platform, one ClickHouse line, one gate class, one failure kind and the server's exact answer. The filter guarantee does not cover these cells. Nothing else is excused: a row covers only that cell, so any other kind, any other answer, any other class, platform or line is still held to the guarantee.

A row that no longer matches anything fails the producer's gate until it is removed, so the list cannot outlive the behavior it records. Adding a row needs a dated sign-off; the `ruling` column names the role that gave it and the date.

## The file

`documented-platform.tsv` is tab-separated. Comment lines start with `#`; the last comment line is the column header. The columns are:

| column     | meaning                                                                          |
| ---------- | -------------------------------------------------------------------------------- |
| `platform` | `linux-amd64`, `linux-arm64` or `darwin-arm64`                                   |
| `line`     | the ClickHouse line (major.minor), one of the lines the where-settings lists use |
| `class`    | the gate class                                                                   |
| `kind`     | the failure kind                                                                 |
| `server`   | the server's exact answer, `server e:<code>`                                     |
| `rule`     | the neutral name of the platform difference                                      |
| `ruling`   | the role that signed the row off, and when                                       |

## Today's rows

Two rows, both on `darwin-arm64` and ClickHouse `26.3`, rule `macos-26.3-thread-stack`: the macOS 26.3 server runs queries on 512 KiB threads, so it refuses deeply nested input with `e:306` (TOO_DEEP_RECURSION) where the library answers it. They cover gate classes `F23` and `F23b`, failure kind `OA_REFUSED`. The measured band is in [`docs/limitations.md`](../../../docs/limitations.md#filters-are-enforcement-grade-against-a-same-platform-server-per-lifted-line-platform).
