# chtypes (SDK repository) — orientation for Claude sessions

This is the **SDK half** of chtypes, Apache 2.0, public: `go/ python/ ts/ rust/` over the frozen `chs_*` C ABI (`include/chtypes.h`, generated; identity is the ABI generation plus a fingerprint, with no revision number), the normative `docs/reference/`, and four side-by-side `examples/` tours, which CI runs. The bindings contain no ClickHouse code; they `dlopen` per-version artifacts and speak the ABI.

The other half is the sibling core repository — private: the wrapper, the build, the artifacts, and the rigs and corpus that score every SDK. The artifacts it publishes are under the Elastic License 2.0 and this repository is Apache 2.0; `NOTICE` is the statement of that split. The rules from that half which bind here:

- **Never rebuild a ClickHouse rule in an SDK.** A binding is a thin passthrough to the artifact; scalar, comparison, coercion and timestamp logic never live in Go/Python/TS/Rust. The one derived result is `Transformed`, per spec.
- **The four bindings give one answer.** A behavior change lands in all four in one cycle (`docs/reference/bindings-v1.md` is the shape). The golden set is **served, not tracked**: core publishes one goldens document per release as an OCI referrer of each platform manifest, each binding's runner fetches it with its own fetch layer under the same signature check as the library, and the shared comparator is `scripts/goldens-v1/compare.py` (`docs/guides/goldens-v1.md`). There is no cases file in this repository.
- **The header is owned here, and it is generated.** `include/chtypes.h` is generated with every binding's declaration layer from `spec/abi-v1/abi.json` by `scripts/abi-v1/gen.py`; an ABI change edits the description and regenerates, never a header or a declaration by hand (`gen.py --check` and `scripts/abi-v1/check-no-hand-decls.py` enforce it, in the required `v1-abi-gen` check). The core repository then pulls the header and relinks every artifact.
- **Never trust exit codes or self-reports.** Every test here skips LOUDLY without a library and refuses a zero-run; `scripts/check-standalone.sh` reads its verdict off a `go test -json` census and `scripts/check-suite.sh` off each runner's own summary line, color stripped. Before either suite runs, both print, via the shared `scripts/lib/provenance.py`, the ABI version and fingerprint this binding was built against; the loaded library's own `build_info` names the artifact.
- **The Go package is dlopen-only by default.** The linked path is behind `-tags chtypes_linked` and needs a core build tree via `CGO_LDFLAGS`. **Only LINKING a binary needs that tree — type-checking the tagged path needs nothing but a C compiler and the in-repo header**, so `scripts/abi-v1/check-linked.sh` builds it in the required `v1-abi-linked` check on every PR, selftest first.
- **Libraries live in one per-user cache**, an OCI image layout at `~/.cache/chtypes/v1/` (`$CHTYPES_CACHE` overrides), with each verified library unpacked beside it. Every binding fetches for itself over OCI and verifies a signed statement before it unpacks: there is no shell fetcher, and `CHTYPES_REGISTRY` is retired. The contract is `docs/guides/fetch-v1.md`; a CLI named `chtypes` with `fetch`, `verify`, `list`, `where`, `resolve` and `prune` ships in every binding.
- darwin artifacts match ClickHouse on macOS; on 26.7+ every platform agrees bit for bit. On 26.3 ClickHouse's own float text parse is OS- and arch-dependent, so 26.3 float expectations come from a server on the same platform (docs/limitations.md).

Gates: `scripts/check-standalone.sh` (Go, from a bare copy) and `scripts/check-suite.sh python|ts|rust`; per language `go test ./...`, `uv run pytest -q`, `pnpm test`, `cargo test`. With a fetched library they run everything; without one every artifact test skips by name and the rest still runs, and a suite that ran nothing fails. `.github/workflows/ci.yml` runs on hosted runners with no secret and no repository variable: each binding builds, lints and runs its unit suite with no library (`--no-artifacts`). The ABI and fetch halves run in their own workflows (`v1-abi.yml`, `v1.yml`): every binding passes every ABI case against a generated stub and every fetch case against a registry the tests start themselves, with no network beyond loopback and no published artifact. The server-truth suites for these SDKs live in the core repository and run from there against this tree as a sibling.

`main` is the 1.x tree: the `v1` branch merged into it on 2026-10-06 and is deleted, and releases are tagged from `main`. The 0.x line is retired (#431). All four bindings are live — `github.com/wave-rf/chtypes/go` (lowercase, the Go norm), PyPI `chtypes`, npm `@wavehouse/chtypes`, crates.io `chtypes`. The module path froze at the first tag (`v0.1.0`); what the pre-1.0 state means is in [`docs/support-v1.md`](docs/support-v1.md#pre-10). **Do not write the current version into this file or any other prose** — it rots within one release; the README's badges read it live from each registry, and each binding's CHANGELOG is the record. Nothing publishes without a `<dir>/v*` tag, and each release workflow refuses a tag whose version differs from the manifest's; the registry setup and the order are in `RELEASING.md` (the one manual first publish per registry is done).
