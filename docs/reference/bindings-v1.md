# The v1 binding API: one shape in four languages

This page is the public API every 1.x binding builds over the ABI v1 C layer ([`abi-v1.md`](abi-v1.md)) and the v1 fetch layer ([`fetch-v1.md`](../guides/fetch-v1.md)). It replaced the 0.x binding contract, which is kept in the 0.x release history.

## 1. Scope and principles

### What this page fixes

For every public operation of a v1 binding: its name and signature in Go, Python, TypeScript and Rust, the C entry point it calls, the type it returns, the error classes it raises, what is safe to share across threads, and how the document it receives is decoded. It does not restate the ABI ([`abi-v1.md`](abi-v1.md) and [`spec/abi-v1/abi.json`](../../spec/abi-v1/abi.json) are normative for that) or the fetch wire contract ([`fetch-v1.md`](../guides/fetch-v1.md)).

A v1 binding has four layers, and only the last one is specified here:

| layer               | written how                                                                     | what it does                                                                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| the generated layer | by [`scripts/abi-v1/gen.py`](../../scripts/abi-v1/gen.py), from the description | declarations, the symbol table, typed call wrappers named without the `chs_` prefix, copy-then-free of every `chs_buf`, the `chs_error` read-out, handle wrappers with a finalizer, the vocabularies |
| the loader          | by hand, once per binding                                                       | the load steps of [`abi-v1.md` §Loading a library](abi-v1.md#loading-a-library), and nothing semantic                                                                                                |
| the fetch layer     | by hand, once per binding                                                       | the seam of [`fetch-v1.md` §9](../guides/fetch-v1.md#9-the-seam): `ensure`, `resolve_installed`, `list_installed`, `verify_installed`, `fetch_signed`                                                |
| the public API      | by hand: **this page**                                                          | idiomatic names over the generated wrappers, the process setup, the 1:1 document decoders, the error classes, and the wiring of the fetch layer into the loader                                      |

[`scripts/abi-v1/check-no-hand-decls.py`](../../scripts/abi-v1/check-no-hand-decls.py) already forbids hand code from declaring or resolving a `chs_*` symbol. The public API therefore calls only the generated layer's prefix-less wrappers, and never touches a raw pointer.

### The principles, each binding on all four

1. **A binding is a thin passthrough.** Every public call makes exactly one ABI call, plus the generated read-out of its buffers and error. No public call contains a ClickHouse rule: no scalar, comparison, coercion, timestamp, zone, quoting or classification logic, and no vocabulary of its own. Anything that would need such logic is an ABI ask, never binding code. §7 lists every v0 surface that existed only because of binding-side logic, and deletes it.
2. **Four bindings, one answer.** The same operations, the same error classes, the same document shapes and the same vocabularies, spelled in each language's idiom: Go `PascalCase` (with Go's initialisms and the product's own spelling: `ID`, `ABI`, `OS`, `SHA256`, `SQL`, `ClickHouse`, `ZooKeeper`), Python `snake_case`, TypeScript `camelCase`, Rust `snake_case`. A concept named once below is named in all four by that mechanical rule unless a table says otherwise. A convenience that exists in one binding exists in all four or in none.
3. **Bytes are bytes.** Every column name, statement, expression, type, quoted spelling, ClickHouse message and rendered value is a counted byte string. It is never a C string and never assumed to be UTF-8: ClickHouse accepts and round-trips column names containing NUL and invalid UTF-8 (`measured`, [`abi-v1.md` §The description](abi-v1.md#the-description)). §3 gives the byte type each language uses. The only text a binding hands out as its language's string type is ASCII the ABI promises (`ch_name`, `build_info` fields, setting names, vocabulary values), plus one lossy display form per error for printing.
4. **Documents are decoded one to one.** Every field of a result type is a field of the document the library returned, or the bytes of an output buffer. A decoder adds no field, computes no field, and drops none it was asked to expose (§5).
5. **One error table.** The five call statuses map to four classes and the loader's refusals to the artifact classes, from [`spec/abi-v1/sdk.json`](../../spec/abi-v1/sdk.json) (§4). No call has a private error rule.
6. **Nothing is probed.** Every described symbol is mandatory, and the loader refuses a library that lacks one. What a build supports is read from `build_info`'s `capabilities`, never discovered by calling.
7. **Shared freely, set up once.** Every object is safe to share across threads (§3). The only process-wide state a caller chooses, the image time zone and the default settings, is fixed once, at setup, before traffic.

### The confirmed ABI, and what this page takes from it

The ABI is confirmed, and everything on this page is FIRM. D1 to D6 ([`abi-v1.md` §The decisions](abi-v1.md#the-decisions)) shape all of it. The confirmation added these, and this page designs each one in:

- **Concurrent calls on one handle are safe**, everywhere the library can make them so (§3).
- **A filter, and a block, holds a counted reference to its schema** (D2's rule, for both).
- **Default settings are fixed at setup.** The library either snapshots them (ClickHouse's own `MultiVersion`) or takes them once, before any handle exists; a library with no setter at all is acceptable. Either way no binding offers a setter for use during traffic (§6).
- **Compile takes exactly one `CREATE TABLE` statement.** There are no engine, TTL or partition-key setters.
- **Time zones are two things.** The image zone, set once per process at setup through `chs_initialize`, governs compiled types (a bare `DateTime` column's zone, MATERIALIZED, PARTITION BY and TTL). The per-call zone is the `session_timezone` key in a call's settings, and governs parsing, rendering, export and DEFAULT evaluation. A zone name is valid exactly when ClickHouse's own `DateLUT` loads it.
- **Generated DEFAULT values come from the library.** A DEFAULT that calls an admitted random or UUID generator is drawn by the library with ClickHouse's own function, reported with `src` `default_generated`, and the caller inserts the library's output so the server stores that value (§5, Generated defaults).
- **An empty input block stays a decline.**
- **The signed channel statement is out of v1.** Nothing in this API depends on one, and the fetch layer reports a line's support as unknown. That is the fetch side's "A10"; the description's own A10 marker means something else, the result documents, which are in v1.

**The regenerated description is the record for every C-side spelling.** The confirmation is applied to [`spec/abi-v1/abi.json`](../../spec/abi-v1/abi.json) in its own change. Where this page names a C entry point, a parameter, a document field or an encoding that the regenerated description spells differently (such as `chs_initialize`'s zone parameter, or a document key), the description wins, and the binding lanes follow it without a change to any public name here. A document field the description adds or drops is one row of §5.

## 2. The operations

One row per public operation. `request` is a version spelling under [`fetch-v1.md` §3](../guides/fetch-v1.md#3-resolve) (two, three or four parts; no `v` prefix, no channel suffix). The type aliases (`BytesIn`, `Settings` and the rest) are defined in §3. Every call that can fail returns Go's `error`, raises in Python and TypeScript, or returns Rust's `Result<T, chtypes::Error>`; §4 says which class.

`cache_root` and `search_dirs` (public issue #530) answer where a lookup reads, for a caller that logs the cache, checks a directory it was given, probes it for writability or names the searched directories in an error, without copying the precedence. A `ServerProfile` carries: `timezone` (a zone name), `settings` (settings) and `macros` (settings), each optional (input:server_profile, [`abi-v2.md`](abi-v2.md)).

**The server profile (ABI v2).** `new_server` describes one ClickHouse server with `chs_server_create`, and the compile option `server` compiles a table on it (`chs_schema_create`'s `server`): the schema's home zone is the server's `timezone`, the server's `settings` layer under the schema's own, and a Replicated engine's ZooKeeper path and replica name expand its `macros`. On a server schema, `timezone()` answers the server's zone when no session zone is in force; a session zone that would change the answer is declined (named in `unsupported_settings`). That applies equally to a profile whose `settings` carry `session_timezone`. The binding serializes the profile with the stock encoder and validates nothing in it: a zone `DateLUT` cannot load, or a setting the server's `SET` check refuses, is the library's own refusal (`SchemaError`), a malformed macro set is its `UsageError`, and a build that does not compile on a server yet declines (`UnsupportedError`). An empty zone and an absent map are omitted from the document; a present map is sent as given, `{}` when empty. **Absent `macros` is not empty `macros`:** absent means the server's macros are unknown, and present, even `{}`, is the server's complete set (Go nil against a non-nil map, Python and TypeScript absent against `{}`, Rust `None` against `Some`). No server option and no schema option is defined yet, so each options document is empty. The server is immutable; a schema holds a counted reference to it inside the library, so the two close in any order, and a closed server is a `UsageError` raised before any call, never NULL in its place (rule r7: NULL means the image's own server, so the library cannot tell a freed server from none); Rust meets the rule by construction, since a `Server` is freed only on its last drop and a compile borrows it. A server from another library is that library's own `CHS_INVALID_ARGUMENT`.

The TypeScript option types are `CompileOptions { settings?, sessionTimezone?, server? }`, `RowOptions { settings?, sessionTimezone?, columns? }`, `RowsOptions extends RowOptions { rowFilter?, exportFormat?, docFlags? }`, `FilterOptions { params?, settings?, sessionTimezone? }` and `EvalOptions { settings?, sessionTimezone? }`. They are deliberately not `#[non_exhaustive]`, which would forbid that construction outside the crate; the result types are.

**The per-call zone is a settings key, and nothing more.** The ABI has no zone parameter on any call: the per-call zone is `"session_timezone": "<name>"` inside the call's settings object. The option exists so the zone is visible in every signature it affects; the binding writes its value into the settings object as that one key, verbatim, and does nothing else with it: no default, no validation, no canonicalization. The library validates it with `DateLUT` and answers a bad name with ClickHouse's own refusal. Passing the option and a `session_timezone` key in `settings` together is a `UsageError`, raised before the call whether or not the two agree, so a call never has two spellings of its zone. In a compile profile it is a default for later calls on that schema; a compiled type always takes the image zone, never the profile's.

**A filter's zone is its own, fixed when it is compiled** (`measured` by the artifact producer on live servers of all four pinned lines: 22 filters, each under 3 insert zones and 3 query zones, with byte-identical answers on every line). It is exactly a server's `SELECT … WHERE` in one session over rows that another session's `INSERT` stored, and the ABI needs no change for it:

1. **The filter's zone is its WHERE's session.** It comes from the filter compile's settings: the `session_timezone` option, or a `session_timezone` key in `settings`. Without one there, it resolves by the precedence every call uses: the schema's compile profile, then the setup defaults, then the image zone. The filter is compiled under that zone, and every evaluation of it runs its WHERE under that zone: `Filter.rows`, `Filter.eval` over a block, and a filter attached to `rows`.
2. **An evaluation's settings are the body's INSERT settings.** The zone in `Filter.rows`' settings, in a block's parse settings, or in the settings of a `rows` call with a filter attached, decides only how the body is parsed (the instants the rows hold), never the WHERE.
3. **Differing zones are an ordinary input.** A filter in one zone over a body parsed in another is answered, the way a server answers it. It is never refused, and never a `UsageError`. A decline stays only for what the library cannot do.
4. **So one parsed block serves many sessions.** K filters compiled under K zones, each evaluated over the same block, each answer as their own session, with no re-parse.

Inside a WHERE, which zone a value meets is ClickHouse's own rule, and no binding applies or checks it. A literal compared with a zone-less `DateTime` or `DateTime64` column (`ts > '…'`, `IN`, `BETWEEN`, `toDateTime('…')`, a `{p:DateTime}` parameter) converts in the filter's zone. A column function (`toHour(ts)`, `toDate(ts)`, `toString(ts)`) uses the column's zone, which for a zone-less column is the image zone. A string literal compared with a column declared with its own zone (`DateTime('UTC')`) converts in that column's zone.

- **A Go `string` is a byte string.** Go has no separate byte-string type, and a `string` holds any bytes, NUL included. The rule is only that it is built from copied bytes (`string(b)`), never through `C.GoString`, which stops at the first NUL.
- **A `str` or `string` input is encoded as UTF-8**, because that is the only way a text value becomes bytes. That is not an assumption about the payload: a caller with non-UTF-8 bytes passes them as `bytes`, `Uint8Array` or `&[u8]`. A body never accepts the text type, as in v0.
- **Rust keeps v0's `RawText`** (the bytes, `as_bytes()`, `as_str() -> Option<&str>` and a lossy `Display`) for every byte output, so it is the one byte-out type in that binding.
- **Settings values are strings, and only strings.** The binding serializes the map into a JSON object of string values with the language's stock encoder and passes it verbatim. It never rewrites a value: no boolean or integer spelling, no float (the v0 Python and TypeScript encoders are deleted, §7). A non-string value is the language's own type error: a compile error in Go and Rust, `TypeError` in Python and TypeScript. A value whose bytes are not valid UTF-8 cannot be passed as a setting or a query parameter in 1.0; the workaround is to inline it in the SQL as `unhex('<hex>')`, built from hex digits only, which cannot break out of the quoted literal.
- **A zone name is text**, because ClickHouse's zone names are, and a name `DateLUT` cannot load is refused by the library whatever its bytes. It crosses the ABI as counted bytes (`chs_initialize`) or as a JSON string (`session_timezone`), UTF-8 encoded.
- **A list of column names** (the `columns` option) is serialized as a JSON array of names under the name encoding of §5.

The rules behind the table, the same in all four:

- **A library is never unloaded.** There is no `dlclose` in any binding, and unloading or re-initializing an image in-process is unsupported, so no binding calls `chs_shutdown` and nothing in the public API closes a registry or a library. A loaded image lives until the process exits. That also retires v0's teardown rules and the reopen crash they guarded against.
- **One image per file, process-wide.** The loader keys an image on its resolved path plus `dev:ino`, so two registries, two spellings or a hardlink of one artifact share one image and one `Library` object. An already-open image is still checked against every new signed statement a request brings (loader steps 1, 4 and 5). A mismatch refuses that request, and the image stays open for the requests it did match.
- **`close` is idempotent, and any order is safe.** A filter or a block holds a counted reference to its schema inside the library, so a binding object neither holds its parent alive nor orders its frees. Closing a schema while its filters are still in use is legal, and they keep working.
- **A finalizer frees what the caller abandons** (Go `runtime.SetFinalizer`, Python `__del__`, a TypeScript `FinalizationRegistry` per handle class, Rust `Drop`). The `live_handles` call exists so each binding's suite can prove it: abandon handles, collect, then require every count to be zero.
- **Using a closed object is a `UsageError`**, raised by the binding before any C call, naming the object. A closed handle is never passed to C as NULL.
- **A handle from another library is the library's to refuse.** D2 tags every handle with its image, and a call given a filter, block or schema from another image answers `CHS_INVALID_ARGUMENT`, which is a `UsageError`. The binding does no cross-library check of its own.
- **No `chs_buf` or `chs_error` ever escapes the generated layer.** Each is copied and freed inside the call that produced it.

### What is safe to share across threads

Concurrent calls are safe everywhere the library can make them so, and the library makes every call on a compiled handle safe to run concurrently with any other call on the same or another handle. The public layer therefore takes **no lock around a call**. It keeps exactly two pieces of synchronization of its own: a **close guard** per handle object, so that `close` waits for the calls already inside that object and refuses later ones, because freeing the caller's reference under an in-flight call would be a use-after-free; and the **setup guard** of §6. If the regenerated description still classes a call as serial, the generated wrapper takes that lock, never the public layer.

**Safe is not the same as fast, but a shared schema is close.** Calls on ONE compiled handle are safe to run concurrently. Since library build `20261006.170903`, one `chs_schema` shared by many threads scales about as well as one handle per thread: on 8 goroutines against 1, Go `Rows` on a shared schema reached 6.8× on a 192-core amd64 runner and 7.6× on a 64-core arm64 runner (one schema per goroutine: 6.7× and 7.6×), against 3.8× and 4.8× with the pool switched off (`measured`: Go binding 1.0.4, 100-row batches, default garbage collector, loaded build `20261006.170903` confirmed from its own `build_info`; every build before it scaled a shared handle about 4× to 6.5×, `measured` by the artifact producer). The library keeps several internal compiles of one schema and routes overlapping calls to different ones, so answers are byte-identical whichever one a call lands on. Compiling a schema per thread or per worker is no longer needed for speed. In Go, `Rows` is also bounded by the garbage collector's cycle rate, which Go 1.0.2 cut (public issue #456).

`CHTYPES_V1_SCHEMA_REPLICAS` (advanced, provisional: it may change, and the default is right for almost everyone) is read once per process:

- unset: the library keeps up to one internal compile per hardware thread per schema, built only when calls on that schema actually overlap;
- `N`: at most N compiles per schema;
- `1`: no replicas; every call shares the schema's one compile (the behavior before build `20261006.170903`). Use it to cap memory or to rule the pool out while debugging.

Memory is about 21 KB per replica for a typical table (`measured` by the artifact producer).

**A row-dependent `DEFAULT` costs per row.** A `DEFAULT f(other_column)` whose value depends on another column is analyzed once per row, which adds about 98 µs per row (`measured` by the artifact producer, Graviton4, 8 cores), until a library build fixes it. A `DEFAULT` that does not read another column does not pay it. Shared-handle `Rows` on `20261006.170903` costs about 22.3 µs per row at 8 concurrent callers, against 34.0 µs on `20261004.052404`.

A misuse the binding detects itself carries `status` `CHS_INVALID_ARGUMENT`, `ch_code` 0, an empty `ch_name` and `column`, and a message naming the misuse, so a handler sees one shape whichever side caught it.

- **Go** embeds one `CallError` struct in each of `SchemaError`, `UnsupportedError`, `UsageError` and `InternalError`, so the fields read directly (`se.ChCode`); `chtypes.AsCallError(err) (*CallError, bool)` reads them from any of the four.
- **Python and TypeScript** give the four one abstract base, `CallError`, under the existing `ChtypesError`. TypeScript's raw message is `messageBytes`, because an `Error`'s `message` must be a string; that string, Python's `str(e)`, Go's `Error()` and Rust's `Display` are the one lossy display form each error has, with invalid UTF-8 replaced for printing only.
- **Rust** carries a `CallError` struct in each of the four variants, and keeps `Error::is_unsupported()`.
- **A loader refusal** carries `reason` (one of `sdk.json`'s `loader.refusals` reasons, with `:<symbol>` or `:<field>` appended where `sdk.json` gives a suffix), `path`, and `want` and `got` where the refusal names both. In Rust they are the `Refusal` struct.
- **A cache fault** (`CHTYPES_CACHE_UNUSABLE`, [`fetch-v1.md` §1](../guides/fetch-v1.md#the-cache-faults)) carries the exact path that failed, the reason (`unreadable_root`, `not_a_directory`, `unreadable_entry`, `unacceptable_record`, `layout_0x` or `unwritable`) and the errno name where there is one (`EACCES`): on Go's artifact error as its path, reason and OS-error fields, on the Python and TypeScript class as its path, reason and OS-error attributes, and in Rust as the cache fault struct the variant holds. Its message is the same sentence in every binding, `<path> is unusable as a cache: <reason> (<errno>)`. It is never the network's `CHTYPES_SOURCE_UNREACHABLE`, so a retry loop never retries a permission error, and never the misuse class.

### The rules

- **The refusal and the decline are PEERS, never one a subtype of the other**, exactly as v0's §The error split rules: a decline that satisfied `errors.As(&SchemaError{})`, `except SchemaError` or `instanceof SchemaError` would let a handler that forgot the distinction turn every decline into a rejection. `UsageError` and `InternalError` are peers of both. Catching all four is an explicit choice: Go `AsCallError`, the Python and TypeScript `CallError` base, Rust's match.
- **A status outside the closed set is an `InternalError` naming its value.** It cannot happen under a matching fingerprint, and the binding still fails closed.
- **Every refusal is a class, never a sentinel.** No v1 error carries v0's `-1`, `-2`, `-3` or `1002`.
- **A second, different image zone is a `UsageError` naming both spellings**, in all four, whoever detects it: the binding's setup guard (§6) or `chs_initialize`, whose process-once rule answers `CHS_INVALID_ARGUMENT` for a different spelling and `CHS_OK` for the same one. A zone name `DateLUT` will not load is a `SchemaError` carrying `DateLUT`'s own code and message. That retires v0's init-conflict error in all four.
- **The fetch layer's and the loader's errors are one family.** A caller catching `ArtifactCorruptError` catches the fetch layer's corrupt layer and the loader's step 5 alike. Each binding's fetch error classes either become these classes or are wrapped by them; that choice is the binding lane's, and the observable classes are the ones in the table.

## 5. Documents and decoders

### The rules every decoder follows

1. **Stock JSON only.** Each document is decoded by the language's own parser (Go `encoding/json`, Python `json`, `JSON.parse`, `serde_json`). That rests on the documents being valid RFC 8259 JSON: no bare `inf` or `nan`, integers beyond 2^53 as strings, ClickHouse's renderings carried as JSON strings, and every data-derived string in the byte-safe form of rule 5, so every document is valid UTF-8 and a strict parser reads it. Those are part of the description's document contract, in the regeneration that freezes the fingerprint (§8 question 2), and they are what lets the hand JSON readers go.
2. **Absent is the default; unknown keys are ignored.** A key the decoder does not know is skipped, so the library can add a field without breaking a binding.
3. **A duplicate key, or a value of the wrong JSON type, is an `InternalError`** naming the document and the key. The loader's strict object reader for `build_info` already does this in every binding; the decoders reuse it rather than each language keeping its own duplicate-key behavior. One Go-specific tolerance applies to documents the library never produces. Go's batch decoder reads with `encoding/json`, which matches a key to a struct field without regard to letter case. So below the top level, a key that differs from a known key only in case is read as that key, where the other bindings skip it as unknown (rule 2). The library never emits such a key. The Go suite compares the batch decoder with the generic reader on every document fixture, so a library change that emitted one would fail a test rather than diverge silently.
4. **Nothing is computed.** Every field below is a document field or an output buffer, with its source named. A vocabulary fact (whether a reason is lossy, a source is stored, a verdict is an answer) is read from the generated vocabulary table the description defines for it, keyed by the value the document carries, never from a list the binding keeps. §3, The generated vocabularies, gives the one answer for a value the table does not list.
5. **Data-derived strings are bytes.** Every string a document carries that comes from data, DDL or ClickHouse's text (a column name, a rendering, a type, SQL, a message) follows the description's `byte_strings` rule: the member `<key>` is a JSON string when the bytes are valid UTF-8 (NUL written `\u0000`, as RFC 8259 allows), and otherwise `<key>` is absent and `<key>_b64` carries the standard base64 of the raw bytes. The two are never both present, and a name is always present in one form. The decoder surfaces the field as the byte type of §3 either way: the UTF-8 encoding of the string, or the decoded base64. Both forms present, a name in neither, or base64 outside the standard padded alphabet is an `InternalError`. Each document's `byte_fields` in [`spec/abi-v1/abi.json`](../../spec/abi-v1/abi.json) lists every such field, so the set a decoder handles is the description's, not a list kept here. A list of names (`unknown_fields`, `unsupported_settings`, `framing.header.names`) holds `{"name"}` or `{"name_b64"}` objects, and an engine row is a list of cells, never an object keyed by a name. The `columns` input list is encoded the same way. `chs_error_column`, `chs_error_message` and the export buffer return raw bytes, with no encoding at all.
6. **String values carry their raw bytes.** Every entry that reports a stored value (`cols`, `computed`, an engine row's cells) carries `value_b64` beside its rendering when the column is a scalar `String` or `FixedString` (`Nullable` and `LowCardinality` included) and the value is not NULL, whether or not the bytes are valid UTF-8. The decoder surfaces it as `value`, the decoded bytes, absent otherwise. `text` is always ClickHouse's rendering. A value nested in another type (`Array(String)`, `Map`, `Tuple`) has no `value` in 1.0; that is a recorded gap.

Every table below lists a document's fields as the regenerated description draws them; a field it adds or drops is one row. The canonical field names are `snake_case`, spelled per language by the rule of §1.

### Generated defaults: insert the library's output, not your input

A column whose DEFAULT calls one of the random or UUID generators this build admits (`rand`, `generateUUIDv4` and the rest; the build lists the feature as `default_generators` in `capabilities.features`) has its value drawn by the library, with ClickHouse's own vendored function, when the input does not supply the column. The column's entry says so: `Value.source` is `default_generated` (`SourceDefaultGenerated`, `Source.DEFAULT_GENERATED`, `Source.DefaultGenerated`, `source::DEFAULT_GENERATED`), and `Value.text` is the value drawn.

**That value is stored only if the caller inserts the library's output.** A server evaluates a DEFAULT only for a column the INSERT does not supply. So a caller that previews a body and then inserts its original input makes the server draw a different value from the one the preview reported, and anything it showed, signed or forwarded from the preview no longer matches the table. The contract, the same in all four bindings:

- **To insert, ask `rows` for an export in the format you will insert, and insert `payload`** (or the rows `spans` mark in it). The export carries every `default_generated` value already filled in, so the server stores it instead of evaluating the DEFAULT.
- **Never insert the original body** when any row carries a `default_generated` column, and never rebuild a row from `values` by hand: the export is the library's own serialization of exactly the values it reported.
- **The binding does nothing about it.** It neither fills, rewrites nor checks a generated value; the marker is the document's `src`, decoded like any other, and the export is the library's bytes. The only DEFAULTs this applies to are plain DEFAULT columns: a MATERIALIZED column is always computed by the server, and an EPHEMERAL one is never stored.

`default_substituted` follows the same rule for the volatile DEFAULTs the library already resolved in v0 (a clock read): the output carries the value, and the caller sends that column explicitly by inserting the output.

## 6. Setup, and from a request to a loaded library

### The process setup

The image zone and the default settings are process-wide in ClickHouse: vendored MergeTree code reads the server zone directly (`measured` by the artifact producer on 26.7), and defaults are read by every call. So both are chosen once, before traffic, through `setup`, and every binding gives `setup` the same rule:

1. **`setup` records; it does not load.** Called before any library is open, it records the zone spelling and the defaults. Called again with the same zone spelling, byte for byte, and the same defaults, it is a no-op. Called with a different zone or different defaults, it is a `UsageError` naming both, and the recorded setup stands, unless a failed open has unlocked the record (rule 4). So two components that disagree before any open is attempted get a refusal, never a silent last-wins. This is the library's own process-once rule for `chs_initialize`, applied by the binding while no image has been set up to ask.
2. **The first successful step 7 latches it.** If `setup` was never called, the first open records the empty setup: the empty zone, which the library reads as `UTC`, and no defaults. The setup latches when the first image completes load step 7 successfully: `chs_initialize`, then `chs_set_defaults` when there are defaults. From then on `setup` succeeds only with exactly the setup in effect, is otherwise a `UsageError` naming both, and nothing unlocks it again. Call `setup` first.
3. **Every image is set up at load step 7, once.** The loader calls `chs_initialize` with the recorded zone, as counted bytes (empty for the empty zone), and then, when there are defaults, `chs_set_defaults` with them, under the setup guard. Nothing calls either again for that image once step 7 has completed.
4. **What the library answers is what the caller gets, and a failed open can be corrected.** A zone `DateLUT` will not load is a `SchemaError` from `chs_initialize`, and a default the library refuses is the error `chs_set_defaults` answers. Either is raised by the open that hit step 7, and that open returns no library. **Until an image has completed step 7, an open that attempted a load and failed unlocks the setup record, whatever failed:** the resolve or the fetch, the signature, loader steps 1 to 6 (an incompatible or corrupt artifact, a missing symbol), or step 7 itself. The record is kept, so a retry with no new `setup` runs under the recorded zone and defaults, never under the empty setup. A different `setup` is accepted and replaces the record. A replaced record is locked again, and so is any record an open claims for its load. The binding unlocks the record under the setup guard, and never one that was recorded or replaced after the failed open began. The binding's own input checks fail before any load is attempted, and unlock nothing: a refused version spelling, or an unverified open without both opt-ins. A failed open is never remembered: the next open of the same request or image runs every step again. Once the setup has latched, a failure unlocks nothing. The library's own process-once rule stays the backstop: an image whose `chs_initialize` succeeded keeps its zone even if `chs_set_defaults` then failed, and a different spelling than the image already has (otherwise possible only across TypeScript isolates, or with a second binding loaded into one process) is `CHS_INVALID_ARGUMENT` from `chs_initialize`, a `UsageError` naming both, the same class rule 1 raises.
5. **Defaults never change during traffic.** There is no public setter, in any binding. If the regenerated description drops `chs_set_defaults` (the decision accepts "no setter at all"), the `defaults` field of `setup` is deleted with it, and per-call `settings` and the compile profile carry everything.

The per-call zone needs no setup: it is the `session_timezone` key of a call's settings (§2, the call options).

### The sequence

```text
registry.for(request)
  1. the registry's memo: a request it has opened before returns the same Library, for the registry's life
  2. resolved = fetch.resolve_installed(request, host platform, fetch options)       never the network
  3. on a miss:  autofetch on  → resolved = fetch.ensure(request, fetch options)       may use the network
                 autofetch off → ArtifactMissing, naming the request and the platform
  4. input = LoadInput{ library_path: resolved.library_path,
                        predicate:    resolved.predicate,          verbatim, never re-encoded
                        platform:     resolved.platform }
  5. image = loader.load(input)                                     steps 1–6, once per image
  6. step 7, once per image: chs_initialize(setup zone), then chs_set_defaults(setup defaults) when there are any
  7. the load-time assertion: the image's own build_info clickhouse_version lies within the request,
     else ArtifactCorrupt (build_info_mismatch:clickhouse_version), whatever the cache answered
  8. return the image's Library, whose resolved() is the record that first opened it
```

The load-time assertion (step 7) is `fetch-v1.md` §9's: an exact request needs exactly that version, a line request a version within the line. A request that is not a version spelling is not checked. It refuses that request only; the image stays loaded for the requests it does answer.

- **Construction opens nothing.** As in v0, constructing a registry dlopens nothing, and nothing opens an artifact except a request for a version or `preload`. TypeScript's `Registry.open` is asynchronous only because its fetch layer is (§8 question 5).
- **The memo keeps v0's "a line request never moves mid-process" rule** (v0 §Version selection, rule 4): `26.8` resolves once per registry, and a newer `26.8` patch installed later is picked up by a new registry, not by the old one. Everything else about resolution is the fetch layer's: which installed build a floating request means, and the spelling rules. The binding orders and matches no versions itself.
- **An open never waits for another request's fetch** (public issue #491). The registry's lock guards its memo and the attempts in progress, and is never held across steps 2 to 8, so an open the cache answers needs neither the network nor another open's fetch. The setup guard is held across a load (steps 5 and 6), which is local, and never across the network. Concurrent opens of one request share one attempt, and so one fetch: each gets that attempt's `Library` or its error, so two racing opens of one request get the same `Library`, and a failed attempt is never remembered, so the next open starts a new one. Go's `ForContext` returns `ctx.Err()` when its context is done before the open has an answer; the fetch goes on for the other opens waiting on it, and is canceled once none does. Python, TypeScript and Rust have no cancellation of an open.
- **`preload`** opens each listed request through steps 1 to 7 at construction, in list order, and never fetches, even with autofetch on. A request no installed build answers is the ordinary `ArtifactMissing`, raised at construction.
- **`autofetch`** defaults to the fetch constants' `CHTYPES_AUTOFETCH`, as in v0, and is off when that is unset.
- **The fetch options** carry everything [`fetch-v1.md`](../guides/fetch-v1.md) configures (bases, cache directory, system directories, trusted keys, token, allow-unsigned, offline, frozen, the lock path, strict cache mode) under the fetch module's own names: Go `FetchOptions` (a public struct the binding converts, because the fetch package is internal and its options include test hooks), Python `FetchOptions`, TypeScript `FetchOptions`, Rust `FetchOptions`. `Resolved` is the fetch layer's record, re-exported unchanged (Go `type Resolved = ocifetch.Resolved`).

### The adapter

`LoadInput` is the loader's own input, so the FFI lanes never depended on a fetch PR. The adapter between the two is three lines in each binding and is the only place they meet. **It passes the predicate exactly as the fetch layer returned it.** Where the loader's input type differs from the fetch layer's `Resolved.predicate` (Go's loader takes raw JSON bytes today, while its fetch layer returns a parsed map), the loader input changes to the fetch layer's type rather than the adapter re-encoding, because a re-encoding is a second derivation of the statement the signature covered.

One conformance case per binding drives the real derivation, as the v1 FFI plan's §5.3 requires: package the stub library as a signed OCI layout under the fixtures' test key, `resolve_installed` it with that key trusted, adapt, and load. A hand-built `LoadInput` cannot test the adapter.

### Unverified and linked opens

- **`open_unverified(path)`** is for a local build, such as the artifact producer's own suites over an unpublished library. It refuses with a `UsageError` unless the caller passes `allow` **and** `CHTYPES_ALLOW_UNVERIFIED_LIBRARY=1` is set, warns once per path, and skips loader steps 1 and 5, because there is no signed statement. It runs step 7 under the process setup like any open. It is not reachable through a registry, and its `Library` has no `Resolved`.
- **Go's `OpenLinked()`** builds the same `Library` over the table the linked filler fills from the statically linked symbols, under `-tags chtypes_linked`. It runs steps 3, 4, 6 and 7 (step 6 is satisfied by the linker), and skips 1, 2 and 5. One code path serves both modes; only the table filler differs.

### What the public API does not wire

`fetch_signed` (goldens and fixtures) and `verify_installed` stay the fetch module's own surface, used by the test harnesses and the CLIs. The CLIs, the `examples/` tours and the 0.x shell fetcher's retirement belong to the switch, not to this page.

## 8. The questions this page raised, and how each was settled

Each question came out of writing this page against the generated layer and the description. Every answer is FIRM; where one is an ABI ask, it goes into the regeneration that freezes the fingerprint.

1. **Typed call wrappers in three of the four generated layers.** Only Go's generated layer had typed, copy-then-free wrappers named without `chs_`. The Python, TypeScript and Rust layers exposed the resolved table and a test-only dispatcher, and `check-no-hand-decls.py` forbids the public layer from naming a `chs_*` symbol. **Settled:** each binding lane extends its own emitter under `scripts/abi-v1/emit/` to emit typed wrappers in Go's shape, and no lane edits another's emitter.
2. **What a column entry carries, and how values travel in documents.** **Settled, as an ABI ask:**
   - every `cols` entry carries `null` (the library's verdict, poison included), which v0 derived in every binding;
   - ClickHouse's renderings (`stored`, `input`, `engine_rows`) travel as JSON strings, never as embedded JSON values;
   - integers beyond 2^53 are strings;
   - there is no bare `inf` or `nan`.

   That is what lets every binding decode with its stock parser (§5, rule 1).
3. **`default_kind` had no vocabulary in the description**, and each v0 binding kept a `DefaultKind` enum by hand. **Settled, as an ABI ask:** a `default_kind` enum joins the description, and `DefaultKind` is generated into all four.
4. **The connect-time profile.** `chs_discover_query` and `chs_discover_columns` cover a table's columns. v0's other two discovery queries, the server version and the changed settings that become the compile profile, have no C replacement. And with the one-statement compile, a caller might compile the server's own `SHOW CREATE TABLE` answer directly. **Settled:**
   - Whether `SHOW CREATE TABLE` output compiles under `chs_schema_create` is to be measured by the artifact producer (`unverified` until then). If it does, that becomes the documented path.
   - The version and changed-settings queries join the C discovery surface as an ABI ask, if they fit the same regeneration.
   - If they do not fit, that is a known 1.0 gap: the caller passes its settings explicitly.
   - No binding ports v0's SQL, either way.
5. **TypeScript's open is asynchronous.** The TypeScript fetch layer's `resolveInstalled` returns a promise, so `registry.for` and `Registry.open` do too, where v0's `for` was synchronous. **Settled:** accepted. v1 is a breaking release, and the other three bindings are synchronous only because their fetch layers are.
6. **The setup's process-once rule before the first open.** **Settled:** while no image exists, the binding itself refuses a second, different `setup`, applying `chs_initialize`'s own rule byte for byte. "Call `setup` first" is the documented pattern, so two components in one process cannot silently disagree.
7. **The per-call zone option and a `session_timezone` key together.** **Settled:** a `UsageError` whenever both are given, even when they agree. No call carries two spellings of its zone, and no binding compares zone names.
8. **A runtime defaults setter.** **Settled:** 1.0 is setup-only in all four, which holds whichever mechanism the library uses. If the library's `MultiVersion` snapshot lands, a setter can come in a 1.x minor, in all four at once.
9. **Go's linked mode.** **Settled:** kept, as `OpenLinked()`. It costs one generated table filler and is the artifact producer's own smoke path.
10. **A document that does not decode.** **Settled:** an `InternalError`, not a fifth call class. The library returned `CHS_OK` and a document that breaks its own schema, which is a library bug.
11. **Byte types in Python and TypeScript.** Names, SQL and renderings come back as `bytes` and `Buffer`, where v0 returned text. **Settled:** bytes in 1.0, with no text-returning conveniences, because a decoded name that silently differs from the stored one is the failure this rule exists to prevent. A later minor can add them in all four.
